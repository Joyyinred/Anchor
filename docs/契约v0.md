# Anchor — 初步设计（Day1–2 产出）

> 范围：`SignalEvent` / `FeatureFrame` / `SessionContext` 三契约 + 四信号精确定义 + 置信度判定式 + 14 场景验收清单
> 上游依据：《Anchor_产品方案.md》《分工v2.md》
> 红线约束：域名分类绝不阻塞引擎（UNKNOWN 保守）；必有本地黑白名单兜底；`FeatureFrame` 缝改动必须当天小会同步



## 1. 四信号精确定义（A 感知半职责）

### 信号 1：上下文相关性 `contextRelevance`（页面级）

- **定义**：当前活跃页面（`domain + path + title`）与会话声明任务的相关性。**问 LLM 的是「标题=X 的这个页面和任务 Z 相关吗」，不是「youtube.com 相关吗」**。
- **三态**：`RELEVANT` / `IRRELEVANT` / `UNKNOWN`
- **UNKNOWN 产生规则（红线1，判出前一律保守）**：
  1. LLM 分类尚未返回（异步 + 惰性，每页每会话只判一次）→ `UNKNOWN`
  2. LLM 失败且本地黑白名单均未命中 → `UNKNOWN`
  3. LLM 低置信（如 `reddit.com/r/相关子版` 这类"待定"）→ `UNKNOWN`
- **短路规则**：命中 `sessionWhitelist` → 直接 `RELEVANT`；命中内置娱乐域黑名单 → 直接 `IRRELEVANT`（仅对整个域都属娱乐的站点；youtube/bilibili 这类混合站**必须走内容级**）。
- **形态硬判**：`contentFormat === 'short_feed'`（Shorts/Reels/竖屏流）→ 直接输出 `IRRELEVANT`，**绕过 LLM**（几乎无论内容都是走神，且省 API 调用）。
- **入口意图参与**：`entryIntent === 'purposeful'`（搜索/课程链接进来）时，即使 LLM 判 UNKNOWN 也不升级为 IRRELEVANT。
- **缓存键**：`domain + pathPattern`（同域不同内容分别缓存）；`code`/`docs` 类已知站点可走域级白名单，省调用量。
- **决策半语义**：只有 `IRRELEVANT` 能推动 DRIFT 置信度；`UNKNOWN` 永远保守。

### 信号 2：锚点脱离时长 `anchorDetachedMs`

- **定义**：`now - 最后一次"锚点有意义交互"的时间戳`。
- **有意义交互**：`isAnchor === true` 且 `interactionType ∈ {ACTIVE_INPUT, PASSIVE_SCROLL, MEDIA_PAUSE, MEDIA_SEEK}`。
  - **`PASSIVE_SCROLL` 归零** ——网页课件/文献精读时滚动翻页、前后呼应查看，是正常的专注学习行为。但若用户在锚点页静止（idle）超时，仍由 STUCK 通道独立覆盖，不冲突。
  - `MEDIA_PAUSE`/`MEDIA_SEEK` 计入——学习式观看的签名（暂停记笔记、回拖重看）正好把"在上课"和"僵尸连播"区分开。
  - **side panel 中的点击/回答也算 ACTIVE_INPUT**：用户在桌宠面板里点"在专注"/"飘了"，本身就是有意识的交互，应正常归零锚点与静止时钟。
  - **注意语义分化**：PASSIVE_SCROLL 在信号 2 归零，但在信号 3 `texture` 中**仍不升级为 purposeful**（否则刷 feed 永远 purposeful，DRIFT 通道失效）。同一事件在两个信号中的不同权重，正是多信号模型的设计意图。
- **会话开始尚无锚点交互**：从 `sessionStart` 起累计（宽限期由 B 侧 `graceUntil` 兜住，A 不特殊处理）。

- **VIEWER 画像锚点语义**：起步教练应把课程视频页本身设为锚点。
- **VIEWER 课后语义**：
  - **课后查资料/记笔记**：离开课程域后，`contextRelevance` 由 LLM 对资料页判 RELEVANT 即安全（主路径否决）；若 LLM 慢/失败（UNKNOWN）+ 入口为 feed_driven，靠 B 侧 30s 持续证据窗口吸收（正常浏览会在 30s 内产生 ACTIVE_INPUT，证据自然中断）。
  - **系列课连播**：锚点语义从"单个视频页"放宽为"课程系列域+路径前缀"（如 `youtube.com/watch?v=course-*` 同一播放列表/合集）；连播视频经 LLM 判 RELEVANT 后，视为仍在锚点范围内，`anchorDetachedMs` 不应因换视频而累计——A 侧需按"系列前缀"匹配锚点，而非严格 URL 相等。

### 信号 3：交互纹理 `texture`

最近 **60 秒窗口**内当前活跃页事件，三态（优先级从上到下）：

| 状态 | 判定规则 |
|---|---|
| `idle` | 窗口内无 ACTIVE_INPUT / PASSIVE_SCROLL / MEDIA_*（含 HIDDEN、系统 IDLE、纯静止） |
| `purposeful` | 窗口内 ≥1 次 ACTIVE_INPUT 或 MEDIA_PAUSE / MEDIA_SEEK |
| `passive` | 窗口内只有 PASSIVE_SCROLL 或连续 MEDIA_PLAY 无任何操作（僵尸连播） |

- 冷启动（窗口内事件 < 2）：沿用最近一次判定，初始 `idle`。

### 信号 4：跳转形态 `jumpPattern`

最近 **5 次域名切换序列**（去重连续同域）：

| 状态 | 判定规则 |
|---|---|
| `stable` | 序列长度 < 3，或 ≥1 次回到锚点域 |
| `task_orbit` | IRRELEVANT 域 ≤ 1 个（**手滑容忍**），其余均 RELEVANT |
| `rabbit_hole` | 出现 ≥2 个**连续** IRRELEVANT 域切换，且每个 IRRELEVANT 域停留 > 10s（**短停豁免**），且未回锚点域 |


- **手滑容忍**：task_orbit 允许 ≤1 个 IRRELEVANT 离群点（5 次中 4 次相关仍是"围着任务域打转"）。
- **短停豁免 10s**：手滑的特征是停留极短；youtube 看视频/刷 feed 极少 10s 内离开，阈值把"误入即关"和"真的刷起来"分开。
- **连续而非累计**：rabbit_hole 的语义是"在无关域之间越跳越远"，强调连续漂移段；手滑是离群点（outlier），不构成连续段。
- 含 `UNKNOWN` 域：不能判 `rabbit_hole`（保守）；IRRELEVANT 离群点 ≤1 且其余 RELEVANT 可判 `task_orbit`；否则 `stable`。
- **边界澄清**：jumpPattern 只是 DRIFT 三证据之一，不是触发器本身——单次手滑后当前页回到 RELEVANT，`contextRelevance !== 'IRRELEVANT'` 必要条件直接否决，不会仅因手滑触发 check-in。

### 辅助测量：`stillnessMs`

- 当前页连续**无任何交互**（含滚动、媒体操作）的毫秒数；任何 `ACTIVE_INPUT`/`PASSIVE_SCROLL`/`MEDIA_*` 归零；仅 HIDDEN/纯静止累计。
- 专供 STUCK 通道，与 `anchorDetachedMs` 相互独立（一个是"没碰锚点"，一个是"没碰当前页"）。

## 2. 三契约 Schema

```ts
// ── SignalEvent：采集 → 感知（A 内部，events.json 入口）──
interface SignalEvent {
  timestamp: number;
  domain: string;
  url: string;                    // 含 path：内容级分类与 Shorts 硬判需要
  title: string;                  // 内容级分类核心输入
  contentKind: 'code' | 'docs' | 'video' | 'short_feed' | 'social_feed'
             | 'article' | 'pdf' | 'ai_chat' | 'music' | 'unknown';
  isAnchor: boolean;
  interactionType: 'ACTIVE_INPUT' | 'PASSIVE_SCROLL' | 'IDLE' | 'HIDDEN'
                 | 'MEDIA_PLAY' | 'MEDIA_PAUSE' | 'MEDIA_SEEK';
  entryIntent: 'search' | 'direct_link' | 'feed' | 'autoplay' | 'unknown';
                                  // 来源：webNavigation transitionType + 上一事件域推断；判不准就 unknown（保守）
  systemIdle: boolean;            // chrome.idle 系统级空闲快照（区分"人走了"与"人在但静止"）
}

// ── FeatureFrame：感知 → 决策（A→B）──
interface FeatureFrame {
  timestamp: number;
  sessionId: string;

  // 四信号：  域-任务相关性分类（LLM，异步 + 惰性 + 缓存、锚点脱离时长（最强最便宜的信号、交互纹理（purposeful / passive / idle、跳转形态（task_orbit / rabbit_hole）
  contextRelevance: 'RELEVANT' | 'IRRELEVANT' | 'UNKNOWN';
  anchorDetachedMs: number;
  texture: 'purposeful' | 'passive' | 'idle';
  jumpPattern: 'task_orbit' | 'rabbit_hole' | 'stable';

  // 新增信号：页面停止（无交互）时长
  stillnessMs: number;                                  // 当前页连续无交互毫秒数
  entryIntent: 'purposeful' | 'feed_driven' | 'unknown'; // 归约：search/direct_link→purposeful；feed/autoplay→feed_driven
  contentFormat: 'short_feed' | 'standard';

  // 辅助（措辞/日志，不参与判定）
  currentDomain: string;
  currentTitle: string;
  currentContentKind: SignalEvent['contentKind'];
}

// ── SessionContext：起步教练 → 两半（B 写 / A·B 读）──
interface SessionContext {
  sessionId: string;
  taskDeclaration: string;
  profile: SessionProfile;
  anchor: { domain: string; url: string };   // VIEWER 画像时 = 课程视频页本身
  sessionWhitelist: string[];
  graceUntil: number;
}

interface SessionProfile {
  archetype: 'CREATOR' | 'READER' | 'VIEWER'           // ★ 阶段一仅这三枚
           | 'COMMUNICATOR' | 'CUSTOM';                // ★ 阶段二（schema 保留，阶段一 LLM 不输出、UI 不展示）
  policy: SignalPolicy;                                 // 决策半真正消费的只有这个
}

interface SignalPolicy {
  muteJumpPattern: boolean;            // 频繁切换/打转是常态 → 静音
  mutePassiveTexture: boolean;         // 长时间被动观看是常态 → 静音
  stuckChannelEnabled: boolean;        // STUCK 通道画像级开关
  anchorDetachedThresholdMs: number;   // 锚点"被抛弃"容忍时长（画像化）
  stuckLadderMs: number[];             // STUCK 阶梯，末位 Infinity = 本会话静音
}
```

### 三预设参数表

| 策略项 | CREATOR（编程/写作/做东西） | READER（深读/文献/课件） | VIEWER（网课/教程视频） |
|---|---|---|---|
| muteJumpPattern | ✅ 快切是常态 | ❌ | ❌ |
| mutePassiveTexture | ❌ 被动刷=走神签名 | ❌ | ✅ 连续观看即学习本身 |
| stuckChannelEnabled | ✅ | ✅ | ❌ 看课天然静止，无区分度 |
| anchorDetachedThresholdMs | 8min（必要条件） | 8min（必要条件） | 20min（**降级为充分条件**） |
| stuckLadderMs | **[15min, 30min, ∞]** | [10min, 20min, ∞] | — |

> CREATOR 阶梯 15min 起步的根据：创作/编程/debug 都需要思考静默，10min 太敏感；第二档翻倍到 30min，之后静音。
> 教程跟练（半 CREATOR 半 VIEWER）阶段一不做 CUSTOM，用 CREATOR 近似；阶段二 CUSTOM 开放 `{ muteJumpPattern: true, mutePassiveTexture: true }` 组合。

## 3. 置信度判定式（B 决策半）

```ts
// ═══════════════ 公共闸口 ═══════════════
const SUSTAINED_EVIDENCE_MS = 30_000;   // 迟滞：证据须连续成立 30s（吸收 texture/jumpPattern 窗口抖动 + 微重启执行期）
const CHECKIN_COOLDOWN_MS   = 300_000;  // 冷却：任一次 check-in 后 5min 内双通道静默
const CHECKIN_BUDGET_MAX    = 3;        // 预算：每会话 check-in 上限 3 次，之后只记录不打扰

// 证据持续器：只有 evidence 连续为 true 满 SUSTAINED_EVIDENCE_MS 才输出 true
interface EvidenceSustainer { since: number | null; }
function sustained(s: EvidenceSustainer, evidence: boolean, now: number): boolean {
  if (!evidence) { s.since = null; return false; }
  if (s.since === null) s.since = now;
  return now - s.since >= SUSTAINED_EVIDENCE_MS;
}

// ── 通道一：DRIFT（"你飘了"，多信号一致，高门槛）──
function isDrifting(f: FeatureFrame, p: SignalPolicy, ctx: SessionContext, state: BState): boolean {
  // —— v3.1 公共闸口 ——
  if (state.restUntil > now) return false;                         // 休息模式硬闸
  if (now - state.lastCheckInTs < CHECKIN_COOLDOWN_MS) return false; // 冷却
  if (state.checkInBudget <= 0) return false;                      // 预算耗尽
  if (now < ctx.graceUntil) return false;                          // 宽限期硬静音

  // 形态硬判：Shorts/Reels + 锚点抛弃（仍需过持续器，防窗口抖动）
  if (f.contentFormat === 'short_feed'
      && f.anchorDetachedMs > p.anchorDetachedThresholdMs) {
    return sustained(state.driftSustainer, true, now);
  }

  if (f.contextRelevance !== 'IRRELEVANT') {                       // 必要条件永不动摇
    return sustained(state.driftSustainer, false, now);
  }

  const anchorAbandoned = f.anchorDetachedMs > p.anchorDetachedThresholdMs;
  const textureEvidence   = !p.mutePassiveTexture && f.texture === 'passive';
  const jumpEvidence      = !p.muteJumpPattern    && f.jumpPattern === 'rabbit_hole';
  const feedEntryEvidence = f.entryIntent === 'feed_driven';

  const evidence = anchorAbandoned
    ? (textureEvidence || jumpEvidence || feedEntryEvidence)
    // ★ VIEWER 降级路径：锚点条件降为充分非必要——
    // 视频课锚点本就弱，"内容翻转到无关 + 被动连进入口"双证齐备
    : (p.mutePassiveTexture && feedEntryEvidence);

  return sustained(state.driftSustainer, evidence, now);
}

// ── 通道二：STUCK（"你卡住了吗"，单信号 + 自适应阶梯，低打扰询问式）──
function isStuck(f: FeatureFrame, p: SignalPolicy, ctx: SessionContext, state: BState): boolean {
  // —— v3.1 公共闸口 ——
  if (state.restUntil > now) return false;
  if (now - state.lastCheckInTs < CHECKIN_COOLDOWN_MS) return false;
  if (state.checkInBudget <= 0) return false;
  if (now < ctx.graceUntil) return false;

  if (!p.stuckChannelEnabled) return false;                        // 画像级开关
  if (f.systemIdle) return false;                                  // 人走了不问
  if (f.texture !== 'idle') return false;
  if (f.contextRelevance === 'IRRELEVANT') return false;           // 停在无关页归 DRIFT 通道管
  if (f.contentFormat === 'short_feed') return false;              // 短视频静止轮播不算"卡住"

  // ★ 回答动作把静止时钟按回零。
  // 用户答「飘了」→ 阈值重置回第一档，但 stillnessMs 已超阈值会立刻再次成立（每秒一次死循环）。
  // lastAnswerTs 切断"承认问题→被无限追问"的反转。
  const effectiveStillnessMs = Math.min(f.stillnessMs, now - state.lastAnswerTs);
  const evidence = effectiveStillnessMs > state.stuckThresholdMs;
  return sustained(state.stuckSustainer, evidence, now);
}

// ── 休息模式（B 侧）──
interface RestState { restUntil: number; restStartTs: number; }
// 用户主动开启 → restUntil = now + 20min（建议上限，可提前结束）；
// 期间双通道全静默，A 感知半照常上报（FeatureFrame 不受休息影响）；
// 到 20min 桌宠轻声提醒一次"休息够啦，要继续吗？"（非 check-in，不占预算）；
// 用户可提前点「结束休息」回到专注态，或点「结束专注」终止整个会话。
```

### STUCK 阶梯状态机（会话内，B 侧）

```
stuckThresholdMs 初始 = policy.stuckLadderMs[0]
  用户答"在专注" → 推进到下一档
  第二档再答"在专注" → Infinity（本会话静音 STUCK 通道；DRIFT 通道不受影响）
  用户答"飘了" → 微重启引导 + 阈值重置回第一档（下次还提醒）
不变式：policy 在会话内只放宽、不收紧（"宁可漏"原则）
```

### `DetectionResult`（B 内部，A 需知晓）

`action: 'DO_NOTHING' | 'CHECK_IN_DRIFT' | 'CHECK_IN_STUCK'`
- DRIFT 措辞："你大概 X 分钟前从{任务}飘到了《{currentTitle}》——还在查，还是走神了？"
- STUCK 措辞："你在这个页面停了 X 分钟——是卡住了，还是飘了？"

### 优雅降级（v3.1，评审修订5）

- **断网/LLM 失败**：`contextRelevance` 只兜底到本地娱乐域黑名单（整个域都属娱乐的站点，如某些纯短视频站）；youtube/bilibili/知乎/reddit 等混合站一律 `UNKNOWN`（保守，绝不因分类失败把学习页误杀）。
