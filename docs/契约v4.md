## 1. 四信号精确定义（A 感知半职责）

### 信号 1：上下文相关性 `contextRelevance`（页面级）

- **定义**：当前活跃页面（`domain + path + title`）与会话声明任务的相关性。**问 LLM 的是「标题=X 的这个页面和任务 Z 相关吗」，不是「youtube.com 相关吗」**。
- **三态**：`RELEVANT` / `IRRELEVANT` / `UNKNOWN`
- **UNKNOWN 产生规则（红线1，判出前一律保守）**：
  1. LLM 尚未返回（异步 + 惰性，每页每会话最多一次）
  2. LLM 失败且本地黑白名单均未命中
  3. LLM 低置信（如 `reddit.com/r/相关子版` 这类"待定"）
- **短路规则（优先级从高到低）**：
  1. ★ v4：命中「**演示域预置分类缓存表**」（见 §5.2）→ 直接返回，**优先级高于 LLM**
  2. 命中 `sessionWhitelist` → `RELEVANT`
  3. `contentFormat === 'short_feed'` → `IRRELEVANT`（形态硬判，绕过 LLM）
  4. 命中内置娱乐域黑名单（仅纯娱乐站，不含 youtube/bilibili 等混合站）→ `IRRELEVANT`
  5. 以上均未短路 → 调 LLM
- **入口意图参与**：`entryIntent === 'purposeful'` 时即使 LLM 判 UNKNOWN 也不升级为 IRRELEVANT。
- **缓存键**：`domain + pathPattern`（同域不同内容分别缓存）；`code`/`docs` 类已知站点走域级白名单。
- **决策半语义**：只有 `IRRELEVANT` 推动 DRIFT 置信度；`UNKNOWN` 永远保守。
- **v4 隐私注释**：全量 url + title 送 LLM 做内容级分类，只发当前页面；完整浏览历史不会离开本机。见 §5.3 隐私声明。

### 信号 2：锚点脱离时长 `anchorDetachedMs` + 锚点匹配规则

- **定义**：`now - 最后一次"锚点有意义交互"的时间戳`。
- **锚点匹配**（v4）：`SessionContext.anchor` 的 `matchMode` 决定「是否仍在锚点范围内」：
  - `'exact'`：严格 URL 相等（CREATOR/READER 默认，IDE/文档页）
  - `'prefix'`：路径前缀匹配（VIEWER 系列课程，如 `/watch?v=lec*&list=PLcourse`，同一播放列表/合集都算锚点命中）
- **有意义交互**：`isAnchor === true`（按 matchMode 判定）且 `interactionType ∈ {ACTIVE_INPUT, PASSIVE_SCROLL, MEDIA_PAUSE, MEDIA_SEEK}`。
  - `PASSIVE_SCROLL` 归零：课件翻页/文献前后呼应属正常学习。
  - `MEDIA_PAUSE`/`MEDIA_SEEK` 计入：学习式观看签名。
  - ★ v4：**side panel 中用户点"在专注"/"飘了"不经过 SignalEvent 管道**，而是 B 侧直接写 `state.lastInteractionTs`，在 §3 的 `lastAnswerTs` 补丁中一并归零。
- **注意语义分化**：PASSIVE_SCROLL 在信号 2 归零，但在信号 3 仍不升级为 purposeful——刷 feed 不会被误给分。多信号的不同权重是设计意图。
- **会话开始尚无锚点交互**：从 `sessionStart` 起累计（宽限期由 B 侧 `graceUntil` 兜住，A 不特殊处理）。

### 信号 3：交互纹理 `texture`

最近 **120 秒窗口**（v4 从 60s 延长到 120s）内当前活跃页事件。**判定优先级从上到下**：

| 优先级 | 状态 | 判定规则 |
|---|---|---|
| 1（最高） | `idle` | 窗口内无 ACTIVE_INPUT / PASSIVE_SCROLL / MEDIA_* |
| 2 | `purposeful` | 窗口内 ≥1 次 ACTIVE_INPUT 或 MEDIA_PAUSE / MEDIA_SEEK，**且**若 `contextRelevance === 'IRRELEVANT'`，则 ACTIVE_INPUT **不升级**（v4：CREATOR 打字型走神盲区修复） |
| 3（最低） | `passive` | 窗口内只有 PASSIVE_SCROLL / 连续 MEDIA_PLAY 无任何操作（僵尸连播），或不受理的其他事件 |

- **v4 持续证据规则**：DRIFT 通道不用"全窗口 passive"而是"**连续 passive 段 ≥ 60s**"——若用户刷 15s → 点视频看 20s（MEDIA_PLAY → passive 继续，因 MEDIA_PLAY 无人为操作）→ 刷 10s，整段被中间播放隔开但仍是被动消费链。连续 passive 段的语义比窗口全 passive 更贴合真实走神。
- 冷启动（窗口内事件 < 2）：沿用最近一次判定，初始 `idle`。

### 信号 4：跳转形态 `jumpPattern`

最近 **5 次域名切换序列**（去重连续同域）。**判定优先级从高到低**（v4 新增）：

| 优先级 | 状态 | 判定规则 |
|---|---|---|
| 1（最高） | `rabbit_hole` | 出现 ≥2 个**连续** IRRELEVANT 域切换，每个 IRRELEVANT 域停留 > 10s（短停豁免），且未回锚点域 |
| 2 | `task_orbit` | IRRELEVANT 域 ≤ 1 个（手滑容忍），其余均 RELEVANT |
| 3（最低） | `stable` | 序列长度 < 3，或 ≥1 次回到锚点域，或不满足以上两态 |

- **手滑容忍**：≤1 个手滑离群点不破坏 task_orbit。
- **短停豁免 10s**：手滑特征即 3s 关掉；看视频/刷 feed 极少 10s 内离开。
- 含 `UNKNOWN` 域：不能判 `rabbit_hole`（保守）；IRRELEVANT 离群点 ≤1 且其余 RELEVANT 可判 `task_orbit`；否则 `stable`。
- **边界澄清**：jumpPattern 只是 DRIFT 三证据之一，不是触发器本身——当前页 RELEVANT 时必要条件直接否决。

### 辅助测量：`stillnessMs`

- 当前页连续**无任何交互**（含滚动、媒体操作）的毫秒数；任何 `ACTIVE_INPUT`/`PASSIVE_SCROLL`/`MEDIA_*` 归零；仅 HIDDEN/纯静止累计。
- 专供 STUCK 通道，与 `anchorDetachedMs` 相互独立（一个是"没碰锚点"，一个是"没碰当前页"）。

## 2. Schema（定稿，跨人主缝唯一源）

```ts
// ── SignalEvent：采集 → 感知（A 内部，events.json 入口）──
interface SignalEvent {
  timestamp: number;
  domain: string;
  url: string;
  title: string;
  contentKind: 'code' | 'docs' | 'video' | 'short_feed' | 'social_feed'
             | 'article' | 'pdf' | 'ai_chat' | 'music' | 'unknown';
  isAnchor: boolean;
  interactionType: 'ACTIVE_INPUT' | 'PASSIVE_SCROLL' | 'IDLE' | 'HIDDEN'
                 | 'MEDIA_PLAY' | 'MEDIA_PAUSE' | 'MEDIA_SEEK';
  entryIntent: 'search' | 'direct_link' | 'feed' | 'autoplay' | 'unknown';
  systemIdle: boolean;
  contentSnippet?: string; // 09-05 新增：用户刚在页面里输入的文字，目前仅 AI 对话类网站（起步只做 claude.ai）；绝大多数域名是 undefined，见 §5.3 隐私声明
  tabId?: number; // 09-11 新增：产生这条事件的浏览器 tab id，原样透传进 lastAnchorSnapshot.tabId，供 pull-back.ts 精确判断"当初那个 tab 有没有自己飘走"，engine 本身不解释这个数字
}

// ── FeatureFrame：感知 → 决策（A→B 主缝，★ v4 新增字段）──
interface FeatureFrame {
  timestamp: number;
  sessionId: string;

  // 四信号
  contextRelevance: 'RELEVANT' | 'IRRELEVANT' | 'UNKNOWN';
  anchorDetachedMs: number;
  texture: 'purposeful' | 'passive' | 'idle';
  jumpPattern: 'task_orbit' | 'rabbit_hole' | 'stable';

  // 扩展信号
  stillnessMs: number;
  entryIntent: 'purposeful' | 'feed_driven' | 'unknown';
    // ★ v4：SignalEvent 5值→A 内部归约为 FeatureFrame 3值
    // ★ v4：entryIntent 不再作为 DRIFT 独立证据，仅作加速器（§3）
  contentFormat: 'short_feed' | 'standard';
  mediaPlaying?: boolean; // 09-11 新增：当前页最近一条 MEDIA_PLAY/MEDIA_PAUSE 是不是 PLAY，STUCK 通道用它豁免"安静看着仍在播放的视频"（video 的 play 事件只在开始播放那一刻发一次，不发不代表停了）

  // ★ v4 新增
  systemIdle: boolean;
  lastAnchorSnapshot: {
    title: string;
    url: string;
    ts: number;
    tabId?: number; // 09-11 新增：见上方 SignalEvent.tabId 注释
  };

  // 辅助
  currentDomain: string;
  currentTitle: string;
  currentContentKind: SignalEvent['contentKind'];
  currentUrl: string; // 09-11 新增：当前页完整 URL，见下方 sessionWhitelist 的 pageKey 粒度条目
}

// ── SessionContext：起步教练 → 两半（B 写 / A·B 读）──
interface SessionContext {
  sessionId: string;
  taskDeclaration: string;        // ★ v4 质量要求：≥8 字符，起步教练 LLM 有追问义务
  profile: SessionProfile;
  anchor: {                       // ★ v4：matchMode 解决 schema §1 正文矛盾
    domain: string;
    url: string;
    matchMode: 'exact' | 'prefix';
  };
  // sessionWhitelist 条目有两种粒度（09-11）：裸域名（"example.com"，场景4"查资料后白名单"
  // 的原始行为，resolveContextRelevance() 按 domainMatches 匹配）或 pageKey（"domain+path"，
  // heuristics.ts MIXED_CONTENT_DOMAINS 命中的域名——youtube/bilibili/reddit/x/twitter/
  // facebook/pinterest/threads/全部 AI_CHAT_DOMAINS——答 DRIFT+FALSE_POSITIVE 时改用这个
  // 粒度，见 frame-pipeline.ts applyCheckInAnswer()）。两种字符串形状不会互相误判（域名不含
  // "/"，pageKey 一定含）。真机复现过域级白名单对混合内容站点的问题：纠正一个 YouTube 视频后，
  // 同一会话内该域名下所有其它视频（包括纯娱乐的）都会被连带短路判 RELEVANT。
  sessionWhitelist: string[];
  graceUntil: number;             // A 不消费，仅 B 决策半作为公共闸口
}

interface SessionProfile {
  archetype: 'CREATOR' | 'READER' | 'VIEWER'
           | 'COMMUNICATOR' | 'CUSTOM';
  policy: SignalPolicy;
}

interface SignalPolicy {
  muteJumpPattern: boolean;
  mutePassiveTexture: boolean;
  stuckChannelEnabled: boolean;
  anchorDetachedThresholdMs: number;
  stuckLadderMs: number[];         // ★ v4 校验：必须 non-empty
}

// ★ v4 新增：SignalPolicy 校验器
function validatePolicy(p: SignalPolicy): SignalPolicy {
  if (p.stuckLadderMs.length === 0) p.stuckLadderMs = DEFAULT_STUCK_LADDER;
  if (p.anchorDetachedThresholdMs <= 0) p.anchorDetachedThresholdMs = DEFAULT_ANCHOR_THRESHOLD;
  return p;
}
const DEFAULT_STUCK_LADDER = [10 * 60_000, 20 * 60_000];
const DEFAULT_ANCHOR_THRESHOLD = 8 * 60_000;
```

| 策略项 | CREATOR | READER | VIEWER |
|---|---|---|---|
| muteJumpPattern | ✅ | ❌ | ❌ |
| mutePassiveTexture | ❌ | ❌ | ✅ |
| stuckChannelEnabled | ✅ | ✅ | ❌ |
| anchorDetachedThresholdMs | 8min（必要条件） | 8min（必要条件） | 20min（降级为充分条件） |
| stuckLadderMs | **[15min, 20min]** | [10min, 20min] | — |

> 教程跟练阶段一用 CREATOR 近似；阶段二 CUSTOM 开放组合。

### 无起步教练时的默认策略（v4 新增）

若 SessionContext 不存在（用户跳过起步教练直接开始工作）：
- 默认画像 = **CREATOR** + 默认 policy（上表 CREATOR 列）
- 锚点 = **当前活跃时长最久的 tab**（前两次 tab 切换后自动推断）
- graceUntil = **2 分钟**
- 桌宠轻提示"想让我更好地陪你？告诉我你准备做什么"，不阻断工作

## 3. 判定式（B 决策半，v4 终版）

### 3.1 时钟基座与帧产出约定（v4 新增）

**FeatureFrame 产出策略**：
```
事件驱动：每次 SignalEvent 到达 → 立即产出一帧
心跳补帧：当事件静默 > 60s，由 chrome.alarms 触发补帧（最小周期 1 分钟）
          → alarms 回调中按"至今最近一帧 + 当前时间"重算各信号，产新帧
```

**时钟基座（Clock Anchor）**：
- 绝对时间源：`Date.now()`（浏览器时钟，跨 SW 回收不丢）
- 相对计时生命周期：`anchorDetachedMs` / `stillnessMs` 依赖 `lastXxxTs` 时间戳
- **SW 持久化方案**（v4）：与判定相关的全部时间戳存入 `chrome.storage.local`，SW 启动时恢复

```ts
// B 侧状态持久化字段
interface BStatePersistable {
  stuckThresholdMs: number;
  stuckLadderIndex: number;
  lastCheckInTs: number;
  lastAnswerTs: number;
  restUntil: number;
}
// 存储键：'anchor_bstate_{sessionId}' → chrome.storage.local
```

**EvidenceSustainer 在 SW 回收后**：`sustainer.since` 不单独持久化——SW 被回收意味着中间无帧，下一帧到来时根据 `now - lastCheckInTs` 重判冷却后，sustainer 从当前帧起重新累计。可能导致"SW 回收 + 冷却刚过"时多等一个 30s 窗口，**是已知限制，不是 bug**。

### 3.3 公共闸口与持续器

```ts
const SUSTAINED_EVIDENCE_MS = scaled(30_000);
const CHECKIN_COOLDOWN_MS   = scaled(300_000);
// ★ v4：不再有 CHECKIN_BUDGET_MAX

interface EvidenceSustainer { since: number | null; }
function sustained(s: EvidenceSustainer, evidence: boolean, now: number): boolean {
  if (!evidence) { s.since = null; return false; }
  if (s.since === null) s.since = now;
  return now - s.since >= SUSTAINED_EVIDENCE_MS;
}
// ★ v4 加速器版：feed_driven 时用更短窗口
function sustainedWithWindow(s: EvidenceSustainer, ev: boolean, now: number, win: number): boolean {
  if (!ev) { s.since = null; return false; }
  if (s.since === null) s.since = now;
  return now - s.since >= win;
}
```

### 3.4 通道一：DRIFT

```ts
function isDrifting(f: FeatureFrame, p: SignalPolicy, ctx: SessionContext, state: BState): boolean {
  if (state.restUntil > now) return false;
  if (now - state.lastCheckInTs < CHECKIN_COOLDOWN_MS) return false;
  if (now < ctx.graceUntil) return false;

  // 形态硬判：Shorts + 锚点抛弃（仍需过持续器）
  if (f.contentFormat === 'short_feed'
      && f.anchorDetachedMs > p.anchorDetachedThresholdMs) {
    return sustained(state.driftSustainer, true, now);
  }

  if (f.contextRelevance !== 'IRRELEVANT') {
    return sustained(state.driftSustainer, false, now);
  }

  const anchorAbandoned = f.anchorDetachedMs > p.anchorDetachedThresholdMs;

  // ★ v4 纹理：连续 passive 段 ≥ 60s（非窗口全 passive）
  const textureEvidence = !p.mutePassiveTexture
    && isContinuouslyPassive(state, f, now, scaled(60_000));

  const jumpEvidence = !p.muteJumpPattern && f.jumpPattern === 'rabbit_hole';

  // ★ v4：entryIntent 降级为加速器，不作为独立证据
  const evidenceWindowMs = (f.entryIntent === 'feed_driven')
    ? scaled(15_000) : SUSTAINED_EVIDENCE_MS;

  const evidence = anchorAbandoned
    ? (textureEvidence || jumpEvidence)
    : (p.mutePassiveTexture && f.entryIntent === 'feed_driven');  // VIEWER 降级

  return sustainedWithWindow(state.driftSustainer, evidence, now, evidenceWindowMs);
}

function isContinuouslyPassive(state: BState, f: FeatureFrame, now: number, threshold: number): boolean {
  if (f.texture !== 'passive') { state.passiveSince = null; return false; }
  if (state.passiveSince === null) state.passiveSince = now;
  return now - state.passiveSince >= threshold;
}
```

### 3.5 通道二：STUCK

```ts
function isStuck(f: FeatureFrame, p: SignalPolicy, ctx: SessionContext, state: BState): boolean {
  if (state.restUntil > now) return false;
  if (now - state.lastCheckInTs < CHECKIN_COOLDOWN_MS) return false;
  if (now < ctx.graceUntil) return false;

  if (!p.stuckChannelEnabled) return false;
  if (f.systemIdle) return false;       // ★ v4：字段已在 FeatureFrame
  if (f.texture !== 'idle') return false;
  if (f.contextRelevance === 'IRRELEVANT') return false;
  if (f.contentFormat === 'short_feed') return false;

  const effectiveStillnessMs = Math.min(f.stillnessMs, now - state.lastAnswerTs);
  return sustained(state.stuckSustainer, effectiveStillnessMs > state.stuckThresholdMs, now);
}
```

### 3.8 休息模式（v4 修订，09-11 二次修订）

```ts
interface RestState { restUntil: number; restStartTs: number; restEndedTs: number; }
// 用户主动点"休息"→ restUntil = Infinity（09-11 前是 now + 20min，到点自动恢复监控——
//   真机复现：demo mode 把这个窗口压缩到 10s，用户还没来得及真的休息，监控就已经悄悄恢复，
//   跟"可随时继续专注或结束专注"这句原文的语义不符，改成不自动到期）
// 期间双通道全静默，A 照常上报
// 15min 首次轻声提醒"休息够啦，要继续吗？"（按 restStartTs 算，不受 restUntil 改动影响）
// 之后每 5min 重复提醒，直到用户回来
// 只能"结束专注"（点 Back to it，restUntil 回到 -Infinity，restEndedTs = now）主动恢复监控——
//   不再有"到点自动恢复"这条路径
// restEndedTs：上一次结束休息的时刻，STUCK 通道用它把休息期间累积的静止时长从"卡住"
//   证据里扣掉（净时长起算点取 max(lastAnswerTs, restEndedTs)）
```

  lastAnchorSnapshot?: FeatureFrame['lastAnchorSnapshot'];

## 5. 关键补充（v4 新增）

### 5.1 已知限制（阶段一承认，de-risk 答辩）

- **多窗口**：当前仅支持单一锚点。编程者双屏（IDE+docs）暂不覆盖——**答辩时诚实承认，标注为阶段二第一优先级**（方案：锚点集 `anchorSet[]`，任一命中即归零）。
- **entryIntent 不可靠**：`webNavigation.transitionType` 在 SPA 跳转下不可用——v4 已降级为加速器，不担主线证据。
- **LLM 分类错判**：用户需手动申诉一次才能进白名单——阶段二可优化为"低置信时显示确认按钮而非直接打扰"。
- **SW 回收**：sustainer 不单独持久化（§3.1 已知限制），可能导致冷却后多等一帧。

### 5.3 隐私声明（v4 新增，09-05 更新）

- **发送给 LLM**：当前活跃页面的完整 `url` + `title` + `taskDeclaration`（仅分类用）；check-in 措辞所需上下文
- **09-05 新增（仅限专门收录的 AI 对话类网站——`src/platform/background/heuristics.ts` 的 `AI_CHAT_DOMAINS`：claude.ai、chatgpt.com/chat.openai.com、gemini.google.com、grok.com、perplexity.ai、copilot.microsoft.com、chat.deepseek.com、poe.com）**：用户刚在对话框里发送的**最新一条**消息文字（截断到约 200 字符），发给分类 LLM 用于判断这句话是否任务相关——**不是完整对话历史**，只是当下这一条。默认开启，不设开关（产品决定，见 `updateNote` 09-05）。原因：这类网站的标签页标题不一定随每轮对话更新，光看标题会让"话题已经飘走"这种场景检测不出来（真机复现：连续问了 3 个无关问题，标题从头到尾没变）。其他域名不受影响，这个字段对它们始终是空的。★ 名单上除 claude.ai 外的站点，选择器还没有逐一真机验证过（见 `src/platform/content/chat-sites.ts` 顶部注释）——验证之前，对这些站点这个功能实际上大概率是"悄悄不生效"（抓不到就返回空，不影响其他功能），不是已经在读取。
- **不发送**：浏览历史、除当前页外的任何页面信息、用户身份信息、（除上一条明确列出的场景外）页面输入内容
- **存储位置**：所有会话数据存于 `chrome.storage.local`（本机）
- **无自有服务器**：数据不出浏览器沙盒（LLM API 调用除外）
- **评委话术**："我们连接收浏览记录的服务器都没有——因为压根就没有服务器"；如被问及是否读取用户输入内容：**如实说明**——仅对当前收录的 AI 对话网站读取最新一条消息，不是完整对话，不是所有网站

### 5.4 量化指标定义（v4 新增）

| 指标 | 定义 | 计算口径 |
|---|---|---|
| 误报率 | 用户回答"我在专注/查资料"的 check-in 数 ÷ 总 check-in 数 | 会话内累计 |
| 漏报率 | 用户自评"有走神但未被发现"次数 ÷ 自称走神总次数 | 阶段二（需用户主动反馈） |
| 缓存命中率 | 从 LLM 缓存命中的分类请求数 ÷ 总分类请求数 | A 侧内部统计 |

### 5.5 taskDeclaration 质量要求（v4 新增）

- 起步教练产出中，`taskDeclaration.length >= 8`（"学习"不满足）
- 若 < 8，起步教练追问"能具体一点吗？比如'准备明天的数据结构考试'"
- 追问最多 2 轮，之后接受用户输入（避免僵住）
